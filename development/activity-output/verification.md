# Activity output implementation and verification

The shared Activity detail adds an on-demand selected-field JSON preview and an admin-only retention route. The default is four hours; request retention is independent. Read and status endpoints enforce full access, ownership, ready metadata, generation and deadline. Status returns no payload. A client renews every five seconds and anchors a maximum 15-second display grant to monotonic request-send time.

Encrypted files and temporary files live in an isolated private root. Audit metadata, settings and transactional unlink queues remain in SQLite; database payloads never contain preview JSON or ciphertext. Each encrypted envelope binds owner, audit ID, capture ID and generation. In-flight capture also binds a per-request nonce and policy revision. A private marker binds each store to the installation, canonical location and random store ID. Cleanup removes only that store’s regular files and preserves unknown files. Updater state retains store history and an independent restore epoch, outside application backups. Restore advances that fence and retires previously bound stores before replacing data, even when current preview settings are missing or changed; interruption tombstones are reconciled before opening storage.

## Dependencies and limits

Use a matching core, checkout launcher or Compose updater, and a plugin with an audited optional projection declaration. Reinstall checkout launchers so the shared storage module is present. Managed Compose requires the matching bundle/updater and distinct default-local named data, state and preview volumes. The distributed wrapper migrates retained settings, validates physical backing, provisions a bound private store and activates the application during normal up. Bind-mounted host Compose installations continue without capture.

Native runtime capture is explicitly disabled: native installer backup/restore paths have not integrated generation retirement. No macOS or Windows installer source was changed, and native installer snapshots/embedded-host behavior were not runtime-verified. The shared UI was verified in macOS Chrome. Manual, unmanaged filesystem restores are outside the managed restore contract; keep capture disabled unless the writer is stopped and its isolated generation is retired before replacement.

The interrupted-restore checks use durable-state injection plus the existing real controller-death rehearsal, rather than power-loss testing at every filesystem instruction. Platform power-loss behavior, Windows ACL provisioning and non-Chrome browsers remain unverified. No live upstream credentials or real user payloads were used.

## Review regression verification

- Retention submissions and writes reject unloaded or pending state. HTTP writes require the opaque policy revision loaded by GET and compare it within the settings transaction. That token includes the policy value and external restore epoch, so numeric revision reuse after restore cannot authorize a stale form. Browser checks cover Enter after a failed GET, forced submit while GET/PUT is pending, a second admin increasing retention, and a change made while the first admin’s confirmation is open. Conflicts preserve the draft, reload the current policy, and require another explicit confirmation.
- The display-grant helper rejects renewal if either earlier deadline has elapsed. Controlled-clock tests execute the deferred network callback before overdue timers on resume; only a fresh reveal may start another grant. Existing browser failure, page-hide and hung-check paths still pass.
- Admin availability is server-derived. API tests cover desktop user agents against a capable server and missing server provisioning/restore support. Chrome renders the unavailable notice at 320 CSS px.
- Unknown nonempty roots cannot be adopted. Markers are checked before cleanup/retirement; only regular files in the store-specific namespace are removed. Sentinel files/directories survive first-open refusal, periodic cleanup and rollback. Relocation or mismatched instance identity refuses access.
- The minute-timer callback retries a failed store open while keeping reads closed, queues physical removals while offline and drains them when storage returns, without explicit reinitialization or a process restart.
- The actual released Compose wrapper’s image path passes fresh up/enrollment/capture, metadata-only backup, restore with missing and changed preview settings, retained-settings migration, and sentinel preservation. An actual default-local volume configured with bind driver options to alias application data is rejected before database replacement; the database hash is unchanged.
- The older managed-upgrade rehearsal was fixed to include shared source and rerun successfully for both bind/source and volume/image modes, covering migration rehearsal, pre-open rollback, successful upgrade and persistent data. The distributed source wrapper variant itself was not rerun in this follow-up.

These are local regression results for re-review, not independent Designer or Architect approval. The release remains gated on both reviews.
